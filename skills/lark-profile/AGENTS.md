# Lark Profile - AI Agent 交互协议

## 交互流程

### 1. 用户查询

当用户请求分析某个用户时，AI Agent 应该：

1. **解析用户意图** - 提取要查询的用户名
2. **执行搜索** - 调用 `profile.py --name "用户名"` 获取用户信息
3. **格式化输出** - 以友好的方式展示分析结果
4. **提供建议** - 根据分析结果给出互动建议

### 2. 自然语言命令映射

| 用户表述 | 实际执行 |
|---------|---------|
| "分析张三" | `profile.py --name "张三"` |
| "查看我和李四的关系" | `profile.py --name "李四"` |
| "生成王五的画像" | `profile.py --name "王五" --format html` |
| "我最近联系谁最多" | `profile.py --top 10` |
| "查看某个人的信息" | 询问具体姓名后执行 |

### 3. 输出格式

标准输出 (Markdown):

````markdown
# 👤 用户画像 — [姓名]

## 基本信息
- 姓名: [姓名]
- 部门: [部门]
- 职位: [职位]
- 邮箱: [邮箱]

## 关系分析
- 关系评估: [关系类型]
- 沟通频率: [频率]
- 最后联系: [日期]
- 累计聊天: [条数]

## 话题分布
[可视化图表或文字列表]

## 关系总结
[总结性描述]
````

## 错误处理

| 错误情况 | 错误信息 | 建议操作 |
|---------|---------|---------|
| 用户不存在 | "未找到用户 [姓名]，请确认姓名是否正确" | 请用户确认或使用更精确的姓名 |
| 无聊天记录 | "未找到与 [姓名] 的聊天记录" | 可能从未私聊过，建议群聊分析 |
| API 错误 | "获取用户信息失败，请稍后重试" | 建议用户检查网络或重新认证 |
| 权限不足 | "权限不足，无法查看消息历史" | 建议用户联系管理员开通权限 |

## 上下文保持

AI Agent 应该维护以下上下文：

1. **当前分析的用户** - 如果用户说 "他" 或 "这个人"，需要能关联到之前查询的用户
2. **分析历史** - 记录已经分析过的用户列表
3. **用户偏好** - 用户是否偏好详细报告/简洁报告/HTML报告

## 示例对话

### 对话 1: 基本查询

```
用户: 帮我分析一下张三
Agent: 正在搜索并分析张三的用户画像...
      (调用 profile.py --name "张三")
      [展示分析结果]
```

### 对话 2: 追问

```
用户: 他是什么职位？
Agent: 根据分析结果，张三是产品研发部的产品经理。
      主要负责 [产品名称] 的需求规划和项目协调。
```

### 对话 3: 连续查询

```
用户: 查看张三的画像
Agent: [展示张三的分析结果]

用户: 那李四呢
Agent: [展示李四的分析结果]

用户: 他们两个之间有什么关系吗
Agent: 根据聊天记录分析，张三和李四都是产品团队成员，
      他们经常在群里围绕项目进度进行协同沟通，暂无发现私下交流。
```

## 缓存策略

AI Agent 应该优先使用缓存数据：

- 如果缓存存在且未过期（<6小时），直接使用
- 如果缓存过期，先检查是否有新消息
- 可以使用 `--refresh` 强制刷新缓存

## 隐私保护

- 仅显示用户主动查询的分析结果
- 不主动推荐或暴露其他用户的关系分析
- 敏感信息（如私人话题讨论）默认不显示
- 用户可以选择显示详细分析或仅显示摘要
